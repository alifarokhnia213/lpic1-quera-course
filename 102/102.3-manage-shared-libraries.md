## Linking
When we write a program we use libraries and routins and we don't write everything from scartch; for example if you need to read text from a standard input, you need to link a library that provides this. think the linking has two forms: 

- 1- Static 
- 2- Dynamic.

### Static Linking
Linking is done when you add this library directly to your program. this method makes your program size bigger because it has all the needed library by the program in itself. One good advantage is that your program will be more compact and can be run without being dependent on other programs or libraries.

### Dynamic Linking
Dynamic Linking is when you state in your program that you need this and that library to run this program. this way your program is smaller and you need to install the libraries separately. this also makes your program more secure and advanced because libraries can be updated centrally and if there is a security bug or a new feature it will be fixed and more advanced without having to update the program entirely.

**Linux Dynamic libraries** have a name convention like `lib<LIBNAME>.so.<VERSION>` and are usually located in `/lib*/` or `/usr/lib*`.

**Dynamic libraries** are also called shared libraries because all programs can use the same libraries which are separatly installed.

### What libraries do we need
Libraries related to system utilities are installed in `/lib` (32-bits) and `/lib64` (64-bits); and other libraries that are installed by software will be located at `/usr/lib` and `/usr/lib64`.

## ldd
The ldd command helps you findout if a program is statically linked or to see needed library if it is dynamically linked. for example:
```bash
➜  ~ ldd /usr/sbin/ldconfig
	not a dynamic executable
➜  ~ ldd /bin/ls           
	linux-vdso.so.1 (0x000070a4033fc000)
	libselinux.so.1 => /lib/x86_64-linux-gnu/libselinux.so.1 (0x000070a40337f000)
	libcap.so.2 => /lib/x86_64-linux-gnu/libcap.so.2 (0x000070a403371000)
	libc.so.6 => /lib/x86_64-linux-gnu/libc.so.6 (0x000070a403000000)
	libpcre2-8.so.0 => /lib/x86_64-linux-gnu/libpcre2-8.so.0 (0x000070a4032b2000)
	/lib64/ld-linux-x86-64.so.2 (0x000070a4033fe000)
```
In example above, `ldconfig` is statically linked and `ls` command is dynamically linked.

## Symbolic link for libraries
If you are writing a program and you use udev functions for example, you often will ask for `libudev.so.1` because you cannot know which version is installed on a client system. the problem is solved by symbolic links. in short, the system creates a symbolic name with version 1 but links the file to the actuall version of library that is installed which for example might be `libudev.so.1.4.0`.

## Dynamic library configs and cache
As with other linux tools, dynamic linking is configured using a text file which is located at `/etc/ld.so.conf`. on an ubuntu it is pointing to other config files in `/etc/ld.so.conf.d/*`. but all those lines in conf.d directory can be also placed in `ld.so.conf` file directly:
```bash
➜  ~ cat /etc/ld.so.conf
include /etc/ld.so.conf.d/*.conf

➜  ~ ls /etc/ld.so.conf.d/
fakeroot-x86_64-linux-gnu.conf  libc.conf
i386-linux-gnu.conf             x86_64-linux-gnu.conf
➜  ~ cat /etc/ld.so.conf.d/libc.conf
# libc default configuration
/usr/local/lib
```

The **ldconfig** command had processed all these files to make the loading of libraries faster. this command creates `ld.so.cache` to locate files that are to be dynamically loaded and linked:
```bash
➜  ~ ldconfig -v | head

	libfakeroot-0.so -> libfakeroot-tcp.so
/lib/i386-linux-gnu: (from /etc/ld.so.conf.d/i386-linux-gnu.conf:3)
	libcrypto.so.3 -> libcrypto.so.3
	librtmp.so.1 -> librtmp.so.1
	libnsl.so.1 -> libnsl.so.1
	libgdk-3.so.0 -> libgdk-3.so.0.2417.32
	libvulkan_intel.so -> libvulkan_intel.so
	libjbig.so.0 -> libjbig.so.0
	libssl.so.3 -> libssl.so.3
```
**If we change** `ld.so.conf` file or `ld.so.conf.d/` we have to run `ldconfig` command to apply the changes.

## Where OS finds dynamic libraries
When a program needs a shared library, the system will search for files in this order:

- 1- `LD_LIBRARY_PATH` environment variable
- 2- Programs path
- 3- `/etc/ld.so.conf` which might load more files from `/etc/ld.so.conf.d/`.
- 4- `/lib/`, `/lib64/`, `/usr/lib/`, `/usr/lib64/`.

**In some cases** you might need to override the default system libraries. some examples are:
- you are running an old software which needs an old version of library.
- you are developing a shared library and you want to test it without installing it.
- you are running a specific program (like from opt) which needs to access its own libraries.

in these cases you can point `LD_LIBRARY_PATH` to the library you need to use and run the program; a colon (`:`) separated list of directories will tell your program where to search for needed libraries before checking the libraries in `/etc/ld.so.cache`.

for example if you execute this command:
```bash
export LD_LIBRARY_PATH=/usr/lib/myoldlibs:/home/user/libs/
```
and then run any command, the system will search `/usr/lib/myoldlibs/` and then `/home/user/libs/` before going to the main system libraries (defined in `/etc/ld.so.cache`)

## Loading Dynamically
Let's see how we can run a program, manually by linux dynamic linker. it is also called dynamic loader and is used to load dynamic libraries needed by an executable. it might be called `ld` or `ld-linux`. you can find yours by running `locate ld-linux` and then using it like this:
```bash
➜  ~ /lib64/ld-linux-x86-64.so.2 /usr/bin/ls
add						
bin						
blumend						
change_theme.sh					
config.json			
Desktop
Pictures
```

**Why we don't need** `ld-linux` when we are running a command?
because the executables we are running are ELF executable and if we check its headers we can see that it says "run this command using ld-linux": `readelf -Wl /usr/bin/ls`.

**There is a hack here** when we can run any linux executable even if its executable permission is not set like explained above:
```bash
➜  ~ /lib64/ld-linux-x86-64.so.2 /usr/bin/ls
```
this way, even if `ls` command is readonly, and if `ld-linux` execute permission is set, we can run the command using ld-linux by passing the location of the command like we did above.

## Notes
- When we write a program we never write everything by ourselves from scratch. most of the times we also use other's programs and routines.

- when we use `lib*.so.1` the OS will search for a short link in `ld.so.cache` file located in `/etc/` for the version that is actually installed.

- if we have another place for our libraries like for example `/var/check` we can add it into a separate file in `/etc/ld.so.conf.d/`.
